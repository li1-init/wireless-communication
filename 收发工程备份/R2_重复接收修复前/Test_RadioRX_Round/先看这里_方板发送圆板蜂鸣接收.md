# R2：修复方板红灯每组闪 4 次

日期：2026-11-16。方板发送，圆板蜂鸣接收。

## 已从实板确认的原因

通过电脑上的 ST-Link，只读检查了当前方板 Flash 和运行中的 RAM；Flash 内容与之前交付的 R1 发送程序完全一致。检查过程中没有暂停、复位、擦除或烧录 MCU。

连续三次读取结果一致：

| 项目 | 实板结果 |
|---|---|
| PART | 0x4438 |
| CHIPREV / ROMID | 0x11 / 0x03 |
| error | 4 |
| stage | 3，加载无线配置阶段 |
| command_error | 0x40，BAD_PROPERTY |
| config_offset | 62 |
| tx_count | 0 |

偏移 62 对应旧配置中的 `RF_SYNC_CONFIG_6`：它从属性 0x1100 开始连续写六项，最后写到 0x1105（SYNC_CONFIG2）。这套 C2 配置包含当前芯片不支持的属性；因此程序停止初始化、显示四次红闪，实际还没有发送数据。

这属于上版程序的芯片/API 版本适配问题，不是要求更换之前已经测通的 SPI 引脚。上版的软件模拟默认接受所有属性地址，未覆盖真实旧版芯片的属性范围，这是此次检查已补上的缺口。

用户另已确认：圆板开机有声音。开机蜂鸣在无线初始化之前执行，说明这条提示路径能够工作；本轮保持蜂鸣器引脚与驱动方式。

## 本次修改

1. 使用完整的 WDS B1 API 配置作为兼容适配起点，替换不兼容的 C2 调制器参数表；不是遇到报错后直接忽略命令。
2. 不再访问 SYNC_CONFIG2、PKT_CONFIG2 和 C2 专用独立 RX 字段；按旧 API 的公共包字段配置固定 16 字节数据。
3. 两端统一采用 **433 MHz、10 kbps、GFSK、20 kHz 频偏**。与 R1 的 9.6 kbps 不同，必须两块板一起更新。
4. 保留 30 MHz 无线晶振参数、原板 XO 调谐值和低功率档；保留硬件 CRC16 与应用层 CRC16。
5. READY 状态判断按 API 的低 4 位状态字段处理，不比较保留位。
6. 保存最近一条实际命令的完整字节，避免查询错误状态时把出错命令覆盖掉。
7. 在加载配置之前检查 PART、CHIPREV 和 ROMID。当前版本针对实测的 0x4438 / 0x11 / 0x03；如果另一块板版本不同，报告 9 号故障，不冒充初始化成功。

配置基于公开的 WDS B1 生成表进行适配，源文件及版本信息见 `配置来源与适配说明.md`。编译和软件兼容性检查已完成；R2 尚未在两块实物板上完成新的空中测试，不能提前记为收发成功。

## 更新后如何测试

1. 两块板都重新烧录本次 R2 HEX。
2. 圆板重新上电：先有一声长音，随后等待时安静。
3. 方板重新上电：红、绿、W 各亮一次；初始化成功后绿灯亮 0.5 秒，然后每次发送完成短闪一次。
4. 圆板每收到一包通过校验的测试数据，响两声短促的“滴滴”；自动测试包约每秒一包。
5. 关闭方板后双短声应停止，重新开启后应恢复。

方板三个按键仍可发送命令 1/2/3，自动包为命令 0。手动发送成功时方板绿灯与 W 灯一起短亮。圆板正常收包只用蜂鸣器，未使用未焊接的 LED。

如果仍有故障：方板红灯每组 N 次；圆板一声长音后 N 声短音。不要把故障长音后的短音组当成正常收包提示。

| 次数 | 含义 |
|---:|---|
| 1 | MCU SPI 超时 |
| 2 | 无线 CTS 超时 |
| 3 | 无线型号不是 0x4438 |
| 4 | 无线命令或状态切换失败 |
| 5 | 配置回读不匹配 |
| 6 | 发送完成超时 |
| 7 | 发送 FIFO 异常 |
| 8 | MCU 时钟初始化失败 |
| 9 | 实物无线芯片修订信息与当前兼容表不匹配 |

进一步查看 Keil Watch 中的 `g_radio`：`profile_version` 应为 2；重点记录 `stage`、`error`、`config_offset`、`part_info`、`request_length`、`request_bytes`。`request_bytes` 保留实际请求，不会被 GET_CHIP_STATUS 查询覆盖。
