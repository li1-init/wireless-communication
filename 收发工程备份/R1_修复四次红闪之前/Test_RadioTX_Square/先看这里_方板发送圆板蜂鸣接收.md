## 2. 最容易判断成功的测试顺序

1. **先只给圆板烧录 RX 工程并上电，方板先关机。** 圆板应发出一声约 0.35 秒的长音，表示接收程序开始运行、蜂鸣器可以发声。随后正常等待时保持安静。
2. 再给方板烧录 TX 工程并上电。方板红、绿、W 灯各亮一次；无线初始化完成后绿灯亮 0.5 秒。
3. 方板自动每秒发送一包测试数据。每次本地无线芯片报告发送完成，绿灯短亮约 0.12 秒。
4. **圆板每收到一包完整且校验通过的测试数据，就“滴滴”两声。** 每声约 70 毫秒，中间停约 90 毫秒。正常情况下大约每秒听到一组“滴滴”。
5. 关掉方板，圆板应停止双短声并恢复安静；重新打开方板，双短声应恢复。这一步有助于确认提示确实由收到方板数据触发。

开机的一声长音不代表收到数据。方板绿灯也只表示本地发送完成，不是圆板的确认回包。**本次通信成功的直接现象是圆板随方板发送而响双短声。**

首轮测试让两块板各自稳定供电，先在近距离测试。使用板上的原有天线。

## 3. 方板三个按键

方板自动发送之外，三个按键可以发送不同命令：

| 按键 | 已确认引脚 | 数据中的 command |
|---|---|---:|
| SWITCH | PA0 | 1 |
| USER | PB2 | 2 |
| CODE | PB1 | 3 |
| 自动测试包 | — | 0 |

单次按下触发一包，长按不连续触发；按键去抖约 20 毫秒。手动包之间至少间隔 300 毫秒，让圆板的双短声可以完整播放。手动包发送成功时，方板绿灯和 W 灯一起短亮；W 灯仍是你已实测的 PA9 通道。

圆板对所有有效测试包统一响两声。若需要区分三个按键的具体数据，可在调试窗口查看 `g_link.last_command`；不必靠颜色或音色猜测。

## 4. 圆板蜂鸣器连接和工作方式

本次从接收 PCB 焊盘记录及历史接收程序两处核对：

`U2 第 45 脚 / PB8 → BP_PWM → Q1/Q2 → C8 → B1 蜂鸣器`

使用 PB8 的 TIM4_CH3、AF2。MCU 用内部 HSI 16 MHz；PWM 频率约 2.9 kHz、发声时占空比 50%，沿用历史接收程序的音调并适配当前时钟。

这条线路经过交流耦合电容 C8，因此不能简单把 PB8 一直拉高当作正常蜂鸣驱动。本程序使用 PWM，停声时比较值归零，输出保持低电平。

圆板 PB5/PB6 的 LED 输出未启用。收包双短声由 1 毫秒系统节拍控制，播放时仍继续接收；即使前台 SPI 出现超时，当前声音也会按时停止，不会因为等待循环而持续鸣叫。

PB8 的连接已经过设计文件核对，但本次尚未取得新 RX 程序的实物发声反馈，不将它提前记为“已实测成功”。

## 5. 故障提示

方板用红灯闪 N 次一组报告故障。

圆板用 **一声长音约 0.5 秒 + N 声短音** 报告故障。注意先听有没有长音前缀，这和收到数据的“两声短音”不同。无线故障后大约每 5 秒重新初始化一次，失败时再报告；等待无线数据本身不算故障，也不会发声。

| N | 含义 | 检查方向 |
|---:|---|---|
| 1 | STM32 SPI 收发/忙标志超时 | MCU SPI 外设状态 |
| 2 | Si4438 CTS 未就绪 | 供电、SDN、片选、SPI 走线；特别检查两板片选不同 |
| 3 | 回读型号不是 0x4438 | 芯片型号、MISO、实际回读数据 |
| 4 | 无线命令报错或状态切换失败 | `g_radio.command_error`、`command_error_id`、`config_offset` |
| 5 | 无线配置数据或回读核对失败 | `g_radio.config_offset` 和配置参数 |
| 6 | 发射完成超时 | 无线芯片状态、发送过程 |
| 7 | 发送 FIFO 异常 | FIFO 状态及命令执行情况 |
| 8 | MCU 内部时钟初始化失败 | MCU 供电和时钟状态 |

接收端的射频 CRC 错包、FIFO 长度异常和不属于本测试格式的数据会丢弃并继续监听，不播放“成功双短声”。统计值保存在调试变量里。

若圆板上电连第一声长音都没有，先检查是否烧录了 RX HEX、程序是否运行，以及 PB8/蜂鸣器驱动链路。此时不能单凭“没有双短声”判定无线收发失败。

## 6. 无线引脚和参数

| 信号 | 方板发送 | 圆板接收 |
|---|---|---|
| SCLK | PA5 / MCU 15 脚 | PA5 / MCU 15 脚 |
| MISO | PA6 / MCU 16 脚 | PA6 / MCU 16 脚 |
| MOSI | PA7 / MCU 17 脚 | PA7 / MCU 17 脚 |
| nSEL | PA2 / MCU 12 脚 | PA4 / MCU 14 脚 |
| SDN | PA1 / MCU 11 脚 | PA1 / MCU 11 脚 |
| 结果提示 | PB3 红、PA11 绿、PA9 W | PB8 蜂鸣器 |

两端均通过 SPI 轮询，不依赖 nIRQ 或无线辅助 GPIO 中断。

沿用项目原有 Si4438-C2 的 WDS 调制器配置：无线晶振 30 MHz、433 MHz、channel 0、GFSK、9600 bit/s、同步字 B4 2B。SPI 使用约 125 kHz。

本测试将收发两端统一为固定 16 字节负载、硬件 CRC16，以及额外的应用层 CRC16；使用相同的配置文件与数据编解码代码。PA_PWR_LVL 设置为 0x10，低于旧配置的 0x7F；该寄存器数值不是直接的 dBm 标注。

每包包含测试标识、版本、按键命令、递增序号、发送端 ID 和 CRC。发送端 ID 只读取 MCU 的唯一标识并计算，不写入 EEPROM。本次没有配对步骤、没有 ACK 回包，是明确的方板→圆板单向测试。

## 8. 为什么上次的新程序烧录快

对实际 HEX 文件的数据记录逐条统计，得到：

| 项目 | 原 Test_ByPCB | 上次 Test_RadioIO |
|---|---:|---:|
| HEX 中实际需要写入的 Flash 数据 | 38,888 字节 | 14,896 字节 |
| Keil 列出的源文件数量（含启动文件） | 42 | 9 |

上次接口测试的写入数据量减少约 62%。只保留所需功能后，编译和烧录需要处理的内容更少；若点击下载时还包含自动编译，工程精简也会影响总耗时。

检查到的 Flash 算法和 ST-Link 驱动选择一致，没有证据表明提速来自更换烧录器。具体下载耗时还可能受 SWD 速率、擦除范围、校验和自动编译设置影响；本次没有实测各阶段时间，所以不能把全部提速精确归因到一项。

本次 RX 工程增加了蜂鸣器 PWM 驱动，固件会比上次纯接口测试大一些，这是正常的功能增加。
