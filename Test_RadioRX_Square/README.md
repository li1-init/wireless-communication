# 方板安全接收工程 V4 — 严格单对端

更新：2026-11-18。搭配 `Test_RadioTX_Secure_Square`。
本版每块板只保存一个当前对端。重新对码成功替换旧对端，
旧设备即使在同一频点，发送数据也不再被本机应用接受。
这取代早期“最多 8 个发送端”的设计；升级后建议重新对码。

## 操作

1. 两块方板烧录同一版本对应的发送、接收固件。
2. 等待开机自检结束（安全版上电有临时密钥准备过程）。
3. 接收板 CODE 持续按住超过约 2 秒，即亮 W 灯常亮，松手。
4. 发送板 CODE 持续按住超过约 2 秒，即亮 W 灯并开始对码，松手。
5. 接收板保存绑定后 W 灯快闪两次，再恢复常亮；发送板收到最终确认、
   保存绑定后 W 灯熄灭。仅一侧提示不能证明双方均已完成。
6. 接收板 CODE 必须先松开，再长按约 2 秒，退出对码、熄灭 W 灯。
7. 发送板按 SWITCH 或 USER 发一次数据；接收板绿灯亮 1 秒并回 ACK；
   发送板收到匹配 ACK 后绿灯亮 1 秒。普通数据在接收端对码模式中不处理。

短按 CODE 不启动对码；一次持续长按只触发一次。发送端 30 秒是失败退出上限，
不是固定等待时间。首次对码临时密钥已在上电准备，连续重试会重新生成。

## 严格一对一规则

- 持久名单只有一个当前设备 ID 和一条链路密钥。
- 普通数据和 ACK 必须匹配本机 ID、当前对端 ID、链路密钥和事务字段。
- 只有显式进入对码模式、完成证明和提交后才替换绑定。
- 每个 EEPROM 记录使用两份交替写入，写入中断保留上一份完整记录。
- 对端更换在本机生效；软件不能远程擦掉旧设备的记忆，但旧设备发来的包已被拒绝。
- 若同一时间有多个接收板进入对码，发送板选择第一个通过验证的回复，
  后续提交只发往这个接收板，其他接收板不会完成绑定。

## 构建和路径

运行 `.\build.ps1`，调用安装的 ARMCC 5。
Keil 工程 `MDK\Test_RadioRX_Square.uvprojx`；
固件 `MDK\Build\Test_RadioRX_Square.hex`。
工程配置保持旧 Keil 兼容的无 BOM UTF-8 格式。
64 KB Flash、10 KB RAM 边界由 `MDK\secure.sct` 强制限制。
第三方 TweetNaCl 原始代码有一条整数符号转换警告，构建无错误。

## 协议与安全边界

V4 固定 60 字节，Curve25519 共享密钥交换，XSalsa20-Poly1305 数据认证加密，
配对另验证安装密钥证明。数据包同时携带发送/接收 ID、持久启动 epoch 和
32 位事务编号。接收端持久保存防重放进度，每个新数据都会写 EEPROM。
高频使用需评估 EEPROM 耐久性；正常断电保存不意味着存储无限寿命。

安装密钥由电脑系统密码学随机源生成，含在源码和 HEX 内，
设备伪随机流从安装密钥、持久 epoch、角色和设备 ID 派生。
取得源码/固件安装密钥的人不在当前防护范围。未设置 MCU 读保护，
没有独立安全审计。无线电仍能被采集，加密不等于信号不可见。

链路单对端记录使用 `0x08080200/0x08080240` 两槽；
旧多设备记录不继续作为可接受名单。发送板现在直接从唯一链路记录
恢复对端，不再使用早期的独立活动接收方索引。
旧 V3、V5 快速版均不兼容 V4。
擦除 EEPROM、更换 MCU、存储损坏需要重新对码；握手中途断电可重新对码恢复。
