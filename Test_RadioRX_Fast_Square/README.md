# 方板快速接收工程 V5 — 严格单对端，无加密

搭配 `Test_RadioTX_Fast_Square`；原 V3 和 V4 安全工程均保留，不覆盖。
本版取消椭圆曲线、密钥生成和加密运算，仅用双向地址绑定和 CRC 检错。
每块板仅保存一个当前对端，不再维护多设备名单。

## 操作

1. 接收板 CODE 持续按住约 2 秒：W 灯常亮，表示已开始对码，可松手。
2. 发送板 CODE 持续按住约 2 秒：W 灯立即亮并开始对码，可松手。
3. 接收板验证配对提交并保存唯一对端后快闪两次，再恢复常亮。
   发送板收到最终确认并保存对端后灯灭。
4. 接收板松开 CODE，再长按约 2 秒退出对码，W 灯灭。
5. 发送板 SWITCH/USER 按一次发一包；接收板有效数据绿灯亮 1 秒并回 ACK，
   发送板匹配 ACK 后绿灯亮 1 秒。

普通断电不丢绑定。短按 CODE 无效，长按一次只触发一次。
接收端对码模式中不处理普通数据。发送端对码失败上限 10 秒；
ACK 等待上限 250 ms；上限不是正常流程的固定延时。

## 一对一与重新绑定

28 字节帧包括发送方 ID、接收方 ID、启动 session、32 位事务 token、
绑定代号、命令和 CRC16。普通数据和 ACK 同时匹配双方 ID、绑定代号；
发送端还要求 ACK 对应本次 session/token。

对码是请求 → 指定双方的回复 → 指定对端的提交 → 最终确认，
回复留 15 ms 收发切换间隔。接收端对第一个候选锁定短暂窗口，
避免另一个发送端在握手中途覆盖。只有显式长按开启的对码窗口能建立新绑定。
收到广播请求不会直接永久绑定。

双方仅保存一个绑定；新绑定成功覆盖旧绑定，旧对端立即失去本机接受资格。
本机不能远程清掉旧对端的 EEPROM，但不会再接受其数据。
如果多台接收端同时进入对码，发送端锁定第一份有效回复，
提交包只发到选中的一台；安装时仍建议只让目标的一对设备进入对码。

## 速度与边界

没有密码学计算，没有密钥预计算开机等待。
无丢包路径四个包不需要等待 150 ms 重试间隔（只在丢包时重试）。
28 字节比安全版 60 字节短；无线保持已验证的 433 MHz、10 kbps 参数，
未为速度随意更改射频配置。
此处只说明实现，不承诺实体板固定毫秒数；还需实测。

CRC 仅检错、不防伪造；同频设备可抓包，刻意复制 ID/绑定代号可伪造通信，
不提供安全认证。正常独立设备不会因同频而被应用当作本机绑定对象。
仅运行期间用 session/token 抑制重复/旧包，接收端重启后不防录音重放。
这样减少普通按键时的 EEPROM 写入，保留配对时双记录保存。

EEPROM：启动计数仍为 `0x08080008/0x08080010`；
V5 单对端双记录使用 `0x08080700/0x08080718`。
不自动继承安全版绑定，首次使用要重新对码。
擦除 EEPROM、存储损坏或超寿命不在普通掉电保存保证内。

## 工程

Keil：`MDK\Test_RadioRX_Fast_Square.uvprojx`
HEX：`MDK\Build\Test_RadioRX_Fast_Square.hex`
构建：`.\build.ps1`，ARMCC 5，64 KB Flash、10 KB RAM 链接边界。
三灯和三按键沿用原发送板实测配置，片选 PA2。

`tests\run_tests.ps1` 测试实际双方状态机、分开的 EEPROM、
第三设备候选干扰、错误双方地址、错误 ACK、绑定代号检查、
224 个单比特损坏、重启恢复、写入中断、旧绑定失效，
以及实际收发应用的 CODE 长按、重复包和 ACK 提示。
未完成实体板验证，测试模拟无线递送。
